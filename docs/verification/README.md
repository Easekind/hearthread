# v0.1 验收记录

2026 年 11 月 20 日，在 Apple Silicon、macOS 15.7.9、系统 WKWebView 18.6 以及本机 Google Chrome 上执行。Node.js 22.23.2，Rust 1.99.1。

| 验收任务                              | 观察结果                                                                                                                                                                              |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原生 WebView 导入 EPUB、PDF、Markdown | 实际文件进入 Rust 存储接口。EPUB 产生章节位置，PDF 绘出非空像素并建立文字层，Markdown 显示原文                                                                                        |
| 原生续读                              | 离开长 Markdown 文档，重载整个页面，再次从原生书库打开。SQLite 中的相对位置和页面实际滚动偏移均恢复                                                                                   |
| 原生存储回归                          | 多块文件写入、重复块拒绝、相同内容去重、不完整上传拒绝、路径检查、批量更新发生修订冲突时整批回滚、重新打开 SQLite 后原件与元数据可读                                                  |
| 真实 EPUB                             | 导入工作区外提供的约 11 MiB 中文 EPUB，提取元数据和封面，打开原文，从目录跳转，再次打开。额外用固定样书验证 CFI 恢复到第 4 章                                                         |
| 真实 PDF                              | 导入约 25 MiB 的 PDF，选择第 10 页，离开阅读并重载书库，重新打开仍位于第 10 页。另测文字层查询和宽度切换                                                                              |
| Markdown 与原件导出                   | 搜索长文并跳到第 26 段，关闭并重开后恢复滚动位置。同一文件重复导入只产生一本书，导出文件逐字节相等                                                                                    |
| 书库管理                              | 重命名、搜索、批量选择、删除、撤销、重载，以及从手机导航进入设置并保存主题                                                                                                            |
| 备份                                  | 导出带真实 Markdown 原件的 ZIP，在全新浏览器上下文中恢复，能够打开并读取原文                                                                                                          |
| 视觉对照                              | 1440×900 和 390×844 下分别对照书库、设置外观页、EPUB 样章。六组截图在 Pixelmatch 阈值 0.08、忽略抗锯齿的条件下均为 0 个差异像素。另比较书墙、导航、标题、搜索框和浮动阅读栏的几何位置 |
| macOS 交付物                          | Tauri release 构建生成 arm64 应用包，使用本机 ad hoc 签名，通过 `codesign --verify --deep --strict`                                                                                   |

浏览器端共 16 项用例，包含两个需要外部书籍的用例。测试不会将个人书籍收录到仓库、安装包或报告。每次运行的截图、差异图和失败跟踪文件放在 `test-results/`。原生 WebView 验收使用单独的测试可执行文件；当桌面会话在后台时，由测试脚本补充动画帧调度，使用实际 PDF.js Worker、canvas、文件和 SQLite。

## 验证边界

Windows、Android 和 iOS 已提供工程或构建配置。当前主机缺少 Windows 运行环境、Android SDK/NDK 和完整 Xcode，尚未验证这三个平台的安装、系统文件选择器和真机触摸表现。手机尺寸截图来自浏览器。四平台构建工作流已加入仓库，尚未远程执行。

截图覆盖上述六个状态。真实导入结果、文件大小、目录和页码取自用户文件，存储页面展示实际位置。11 月 20 日验收的版本提供简体中文界面与固定快捷键。原稿辅助设置中的语言包、自定义快捷键、迁移书库目录和在线更新未接入。首版备份与恢复可用于手动迁移。

## 2026 年 11 月 25 日 · 界面语言

在 macOS 15.7.9、Chrome 158 和系统 WKWebView 上验证。两套语言资源共 207 个消息键，核对了英文单复数形式及两种语言的插值参数。

- **首次启动与切换**。在浏览器系统语言设为简体中文的新书库中，首次启动显示英文。在 1440 和 390 像素宽度下，从设置切换为简体中文，重新载入，再切回英文。菜单、无障碍名称和窗口标题随语言更新。
- **阅读与备份**。用英文界面导入中英文混排的 Markdown，在中文界面重新打开后核对正文和滚动位置。把中文书库备份导入全新英文书库，恢复完成提示、语言和排版偏好均恢复为备份中的设置。
- **浏览器回归**。`bun run test:e2e` 共 30 项通过，包括使用书库外的 `sample-alice.epub` 和 `sample-alice.pdf` 验证目录跳转与续读。中文书库、设置、语言控件、排版预览和样章在桌面与手机尺寸下的 10 组截图均通过原有像素差异判定。
- **原生回归**。`bun run check`、`bun run test:native` 和 `bun run test:webview` 通过。macOS 原生测试从英文切换至中文，导入并打开三种格式，重载后核对 SQLite 保存的语言和 Markdown 阅读位置。
- **平台范围**。本轮原生验证覆盖 macOS。Windows、iOS 和 Android 的原生语言切换尚未实测。

## 2026 年 11 月 25 日 · 单屏与双屏阅读

在 macOS 15.7.9、Google Chrome 158 和系统 WKWebView 上验证。运行 `bun run check`、`bun run test:e2e` 和 `bun run test:webview`，35 项浏览器用例通过，包括两本书库外的实际文件。

- 在桌面 1440×900 和平板 744×1133 下从阅读排版切换到双屏，手机 390×844 下确认无布局选项且正文保持单屏。三种尺寸均通过原稿像素对照。
- 同一本中文 EPUB 从双屏依次切换到手机横屏 844×390、竖屏 390×844、平板竖屏 744×1133，实测依次显示一栏、一栏、两栏，始终在原章节。另验证手机重置排版后恢复宽屏时仍保留双屏偏好，PDF 的画布数量与页码范围随窗口更新。
- 导入中文 EPUB，切换双屏，从目录打开第六章，确认左页显示原书插图、章名与开篇，右页接续同一段正文。另测流式与固定版式 EPUB 的翻页、重排和 CFI 续读，以及竖排 EPUB 在高窗口中的栏数。
- 导入多页 PDF，从第 10 页切换为第 9–10 页跨页，前翻和后翻后退出、重载并重新打开。另用两页 PDF 核对文字层与画布，Chrome 和 WKWebView 均显示两个相邻页面。
- 导入长 Markdown，搜索段落后切换双屏，翻页、退出、重载并恢复阅读位置。WKWebView 从 SQLite 重新打开后恢复横向位置。将双屏书库备份恢复到新的浏览器书库后，正文和布局偏好均可读。
- 手机尺寸用于浏览器布局对照。本轮原生验收覆盖 macOS，Windows、iOS 和 Android 真机尚未实测。

## 2026 年 11 月 25 日 · 内置书与导入书的阅读对照

在 macOS 的 Chrome 中，用书架内置的《瓦尔登湖》、PDF 样书和《山间散步》与各自重新导入的原件对照。在 390×844 视口从相同章节或页码打开，翻一页、退回书架、重载应用、重新打开。三组打开后的正文截图分别逐像素相同，翻页后和续读后的截图也分别相同。EPUB 和 Markdown 用模拟触摸横滑，PDF 用滚轮翻页。

本轮 46 项浏览器端到端测试全部通过，包含个人书库 EPUB 和 PDF。设计对照覆盖 390、744 和 1440 像素宽度。系统 WKWebView 使用独立 SQLite 书库导入三种文件，验证固定页绘制、双页与续读。本轮未在 Windows、iOS 和 Android 原生端运行。

## 2026 年 11 月 25 日 · 底栏页码与滚轮翻页

## 2026 年 11 月 27 日 · 轻滑与连续翻页

在 macOS Chrome 的 390×844 阅读页中复现了漏翻。三种格式轻滚 5 像素均停在第 1 页，向上滑 100 像素也停在原页。PDF 横滑 20 像素同样没有翻页。新增三项按格式运行的回归用例，在修改前均因轻滚后的页码断言失败。

修复后，EPUB、PDF 和 Markdown 均通过轻滚、反向轻滚、短距离慢速横滑、竖滑、斜滑及三次连续短滑验证。连续 14 次同向滚轮事件只前进一屏。用 wheel-gestures 2.3.0 中录制的快速甩动、慢拖与连续两次滑动事件在浏览器中回放，实际分别前进一、一、两页。另验证了带惯性标记的输入、单屏与双屏页码、适宽 PDF 的页内滚动和退出后续读。导入未声明全书翻页方向的竖排 EPUB，向右滑前进一页、向左滑回到原页。模拟单击、取消触摸与双指缩放后，PDF 的页码保持在第 1 页。

最终生产构建的 64 项 Chrome 端到端用例全部通过。macOS WKWebView 在独立 SQLite 书库中导入三个格式的原件，用小幅滚轮事件验证翻页和续读。触摸使用 Chrome 的触摸模拟，触控板使用录制事件回放。本轮未做物理触控板手测，也未在 Windows、iOS、Android 原生端测试。
